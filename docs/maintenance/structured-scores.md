# 结构化码谱：分页、合页与长页统一规则

> 当前维护入口：2026-11-28，主工程版本6.1.4.6。本文集中维护当前Canvas规则，不再按修改轮次追加相互矛盾的分页说明。应用版本以工程文件为准；文件格式仍Version=1。
>
> 适用：本地`.cscore`、在线下载码谱、携带结构数据的PNG，以及编辑器预览和主显示。仅简谱；不涉及五线谱、演奏时间线或OMR。独立工具过去导出的图片不是本文规则的当前运行结果。

## 1. 一页读懂最终规则

| 层级 | 统一规则 |
|---|---|
| 人工数字 | 最高优先；完整覆盖，不追加原谱切点，不被自动优化覆盖 |
| 自动分页单位 | 解析、排版后的完整正文band；不是源文件行数、Q条数或像素裁条 |
| 自动容量 | 每页最多5个完整band；单个正文band不拆开 |
| 一页条件 | 当前歌词节完整正文总计≤5行，就一页显示 |
| 副歌 | ≤5行的连续副歌不可内部切开；>5行先与前后主歌隔开，再在自身内部拆分 |
| 分配顺序 | 总行数→满足容量和副歌边界的最少页数→前页同量、末页收余 |
| 短尾页 | 允许；不因最后仅1行而把少行页挪到首页或中间页 |
| 原谱`*` | 自动排版的弱参考；不是强制再切一次的硬边界 |
| 合页 | 同旋律不同歌词，并且实际合成结果恰好1页才可用；无能力、多页或无效数据置灰 |
| 打开首选 | 可用单页合页优先，否则分页；显式首选分页保留；首选合页不能绕过单页条件 |
| 长页 | 顺序显示各节全部正文，仅保留一次顶层标题，不应用分页切点 |

自动分页不硬套“每页4行”：当前上限是5。4行仅是容量假设示例，不是本轮新增的设置项：若上限为4，则10→442、12→444、16→4444；当前5行上限下10→55。

## 2. 完整行数如何计算

1. 用`ExtendedScoreNotationRenderer`解析上游简谱，完成音符、声部、歌词对位、注释和实际换行。
2. `Record(..., measureOnly: true)`返回`Bands`；分页按这些完整band计算。
3. 标题、曲号、调拍号不算正文行；标题属于页头。原位文字段落、曲段局部头部等已进入正文band的内容参与计数。
4. 一条很长的Q实际排成两行就计两行；多条C歌词共同附着同一旋律band，不单独按代码换行数计数。
5. 分页模式按实际歌词节选择正文，再逐节计数、分配。公共副歌保留在每节中，不自动删掉重复副歌。
6. 合页按全部不同歌词同旋律排列后的实际band计数，不能拿分页的总行数或页数推断合页是否可用。

所有切分都保持band顺序、无遗漏、无重复；不截断音符、歌词或连线，也不为凑页数改谱文。

## 3. 自动分页算法

唯一自动分配入口：`StructuredScoreLayoutRenderer.SelectAutomaticPages`。`CreatePageLines`、渲染选页和合页计数共用它；旧`Balance`、`BalanceWithBreaks`、`SplitAtBreaks`已移除，不能再恢复成第二套规则。

### 3.1 普通正文

当前上限`M=5`。先求最少页数`P`，然后：

```text
前页行数 F = ceil(总行数 N / 最少页数 P)
末页行数 R = N - F × (P - 1)
方案 = F重复(P - 1)次 + R
```

满足所有语义边界时直接采用，不用“避免短尾页”的惩罚改写它。

| 总行数 | 当前自动结果 | 原因 |
|---:|---|---|
| 1～5 | 一页 | 完整放下 |
| 6 | 33 | 最少2页，前页3、末页3 |
| 7 | 43 | 最少2页，余数在末页 |
| 8 | 44 | 最少2页 |
| 10 | 55 | 不是每页4行 |
| 11 | 443 | 最少3页 |
| 12 | 444 | 最少3页 |
| 13 | 553 | 不再变成544 |
| 16 | 4444 | 最少4页 |
| 17 | 5552 | 不再把少行页移到前面 |
| 21 | 55551 | 接受1行尾页 |

### 3.2 副歌完整优先

副歌来自解析后的行节点，不靠源文本简单数行：

- 音符注释包含“副歌”时，标记后续连续正文为副歌。
- 已有编号主歌后出现无编号公共歌词，可识别为共享副歌。
- 显式“主歌”结束副歌，并重置推断状态；不同曲段独立处理。
- 显式副歌后的编号歌词仍处于副歌状态，不能因为有C1/C2就解除保护。

先将≤5行副歌内部的切点禁用；>5行副歌首尾必须分开。再在允许边界中求最少页数。

若“前页同量、末页收余”会切断完整副歌，才回退到同样最少页数内的语义合法分法；按行数接近程度选取，原谱切点仅低权重参考。完整副歌的优先级高于前页整齐，人工数字的优先级又高于副歌保护。

| 内容 | 自动结果 |
|---|---|
| 主歌1＋副歌4 | 5，同页 |
| 主歌2＋副歌4 | 24，完整副歌单页；不能33 |
| 主歌2＋副歌8 | 244，长副歌只在自身内部拆 |

未被语义标记识别的副歌不能保证被保护：可补上游支持的“副歌/主歌”注释，或用人工脚本明确分配；不按歌曲标题硬编码特例。

## 4. 人工分页脚本

入口统一叫“分页脚本”。输入的是每页完整正文行数，不是Python代码，也不执行任何脚本程序。

### 4.1 输入与收余

- `4444`：默认连续单字符数字，表示4、4、4、4。
- `4 423`在13行时表示4、4、2、3。
- `12 4`在16行时保留完整多位整数方案12、4。
- 完整覆盖总行数的空格整数方案优先按原义保留；否则，空格多段且每段有效、不超过总行数时按整数处理；其他情况按连续数字展开。含0的有效正整数段按多位数处理，不把0当成独立一页。
- 输入方案不完整时，最后一个输入位置直接接收剩余行数；前面的请求超过剩余时取剩余，后续多余位置不再产生页面。

| 输入 | 总行数 | 实际保存方案 |
|---|---:|---|
| `444`或`4 4 4` | 10 | 442 |
| `333` | 12 | 336；最后一个位置收余，不自动增加第4页 |
| `3 3 3 3` | 12 | 3333 |
| `4 423` | 13 | 4423 |
| `12 4` | 16 | 12 4 |

这里的收余是**人工输入语义**，不是自动分页器替你猜出444。输入意图明确时按人工方案执行；可以超过5行，由原图完整显示，不再次自动拆开。每页必须正整数，拒绝负数、独立0、非数字、溢出和文件中的漏行/重复覆盖。

### 4.2 保存与清空

- 有人工数字：`PageLinesManual/CombinedPageLinesManual=true`。
- 清空或点“默认”：回到统一自动规则；不是恢复旧的强制`*`切分。
- 编辑器摘要和保存调用同一个`ParsePageNumbers`。只显示默认提示数字时，文本框仍为空，不视为人工输入。
- 每个数字<10时紧凑显示；有多位数时以空格显示。
- 现有文件仅改数字/颜色，通过已有即时应用回调保存；改谱文/标题仍走保存按钮。未分析完成、失败、过期请求和关闭都不能把旧结果回写。
- 改谱文触发重新分析并重建默认方案；原人工数字不偷偷套到不同总行数的新谱文。

## 5. 合页可用性和默认打开

共用入口：`StructuredScoreDocument.PrepareSinglePageCombinedAvailability`。

1. `CanCombine`检查同一旋律声部是否有不同、非空、实际对位的歌词。只看节号数量不够；未对位尾词不制造合页能力。
2. 对合页字段在内存快照中做旧数据兼容，不把分页模式的版本和数字提前改成合页版本。
3. `GetCombinedPageCount`使用实际完整band和同一选页函数，且人工数字仍最高优先。
4. **结果必须恰好1页**。空结果、解析失败、多页、人工无效覆盖都不可用，正常取消继续按取消处理。
5. 主显示悬浮按钮和编辑器版式下拉使用同一个判断：无同旋律不同歌词或多页自动置灰。编辑器不保存新产生的多页合页方案。

| 情况 | 新会话默认显示 |
|---|---|
| 合页可用，首选为空或合页 | 合页 |
| 合页可用，明确首选分页 | 分页 |
| 合页多页，明确首选合页 | **分页**；不允许首选绕过单页规则 |
| 没有合页能力/合页无效 | 分页 |

`Layout`是当前版式；`PreferredOpeningLayout`只影响新会话首选，不覆盖同首用户切换。`GetStructuredViewAsync`再次检查合页，失效时回退分页。新会话页号从0开始。

底层`Combined`渲染API仍能读出多页旧数据用于验证和兼容，不删除旧文件字段；这不代表主显示合页入口允许多页。人工合页如`[6]`若仍为一个完整页面，可通过单页判断；自动方案仍遵守5行上限。

## 6. 分页、合页、长页显示

- 分页和合页每页重复标题/曲号/调拍号；节号仅在页面首个相关完整band标一次，不每行重复。曲段局部头部保留在正文中。
- 分页、合页直接走结构谱原图显示，不先Fit再调用原图。结构谱原图子模式默认置顶，保留用户已保存的适中/拉伸/置顶选择。
- 同首翻页保留手动缩放；新歌重置该手动缩放，不重置用户配置。复用底部原图缩放控件。
- 位图宽1920，分页/合页最小高1440；实际内容更高时增加高度，不裁断、不强缩小字体。5行规则是内容分配，不是所有图都必须1440px高。
- 长页由各节正文顺序直接绘制，不重新拼带重复页头和页底留白的PNG；顶层标题只一次，曲段头部和公共副歌保留，不因为长页而自动去重。
- 长页不需要`PageLines`，忽略原谱分页标记和人工切点；主要用于滚动/合成播放。
- 悬浮工具保留三种版式、歌词、编辑谱文、固定按钮和第二行紧凑页码/箭头。`StructuredScoreToolbarPinned`默认true，已有false保留；主题和固定状态沿用现有配置，不每次翻页重建整套控件。
- 在线歌谱的“显示图片”是网站图片兜底；自定义本地目录不出现此按钮，不能混为合页。

## 7. 实体字段与旧文件兼容

`.cscore`为JSON，`Format=CanvasCast.StructuredScore`、`Version=1`、`NotationFormat=shigeben`；原始`Notation`是数据源。PNG可在私有`csCo`块携带同一JSON，CRC校验，不要求旁文件。内置`Lyrics`保存歌词文档；null旧文件可由谱文提取，空正文尊重用户清空。

| 字段 | 含义/规则 |
|---|---|
| `PageLines` | 分页各歌词节的数组；`[[4],[4],[4],[4]]`。人工单数组可顺序覆盖全曲 |
| `CombinedPageLines` | 全部歌词同旋律排列后的页行数数组，如`[4]` |
| `PageLinesManual`、`CombinedPageLinesManual` | true人工；false自动；null旧文件来源未知 |
| `Layout`、`Page` | 当前版式/0起页号，不等于打开首选 |
| `PreferredOpeningLayout` | 可选分页/合页首选；不能绕过可用性 |
| `RenderRevision` | 当前排版缓存修订，不是应用或文件格式版本 |
| `PaginationWasUpdated`、`PaginationNotice` | 内存兼容结果，不持久化 |
| `TextColor` | `#RRGGBB`原生绘制；null跟随显示，不走像素变色 |

当前修订：`native-score-v2.12-unified-front-remainder`。

- 缺方案：生成默认，标为false。
- 明确false旧自动：按当前规则重建；迁移后沿用既有成功打开/保存路径写回。
- 明确true人工：有效数字保留；总行数改变且不完整覆盖时拒绝，提示调整或清空。
- null但已有数字：保守按人工保留，不猜测其来源；主界面与编辑器一致。需要新自动规则时清空数字。
- 分页与合页各自保留计划；合页可用性检查不覆盖分页数据或提前更新其修订。
- 只读检查不写用户文件；谱文、Id、歌词和颜色不因自动分页而改变。

## 8. 缓存、异步与稳定性边界

- 主显示视图缓存忽略自动数字规范化的临时变化，人工计划仍进入身份；后续预热复用已有view，不重新建首帧会话。
- 旧文件来源未知但已有数字时，在构造缓存键阶段就按人工方案处理；不同切点不能共用错误画面，null来源规范化为true也不再生成第二个缓存身份。分页画面的身份同时包含人工合页方案，避免合页按钮沿用旧可用状态。
- 磁盘缓存键包含实际谱文、版式、有效计划、字体、配色与`CurrentRenderRevision`；规则变化升级修订，避免命中旧页面。
- 先按measureOnly取得页数，再逐步发布首帧及页面；预告页数必须与最终渲染一致。
- 缓存成功索引`pages.json`最后提交；正常取消不提交半套成功结果。交互预览/显示的预期取消与真实错误分开，公共导出保留标准取消异常。
- 新图交付后模式切换保留已准备帧，不清空刚生成的结构谱会话。
- 文件写回沿用身份/内容校验与写入门，不把过期后台分析覆盖到用户的新编辑或移动后的文件。
- 已有关键帧拒绝直接改结构谱版式/坐标；同名但Id不同拒绝覆盖。真实失败保留原文件/旧显示并报告。

这些是当前维护约束，不是“完整冷启动10ms”的性能承诺；未增加内存限额或整本常驻预热。
